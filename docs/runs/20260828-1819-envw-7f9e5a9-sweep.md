### 2.1 L'aritmetica non lascia margine di interpretazione

```
ES_JAVA_OPTS = -Xms1g -Xmx1g            → 1024 MiB
-XX:MaxDirectMemorySize=536870912       →  512 MiB
                                somma   → 1536 MiB
mem_limit dichiarato nel compose        → 1536 MiB
                              residuo   →    0 MiB
```

**Zero byte** per metaspace, code cache, stack dei thread, allocazioni native e page cache. Il
tetto è *esattamente* pari a heap + direct memory: è matematicamente insoddisfacibile.

### 2.2 Riscontri diretti dal cgroup

```

/sys/fs/cgroup/memory.events = max 4  → max 5 in pochi minuti di osservazione
```

**perché ES esce da solo** (`-XX:+ExitOnOutOfMemoryError`, `ExitCode=0`): chi si fidasse di
`OOMKilled` concluderebbe che non c'è un problema di memoria. `RestartCount = 7`, con riavvii

"incollato al tetto" e non "muore contro il tetto" — ma va saputo: **§4.3.1(d) non è un
rilevatore di crashloop**, e i due controlli servono entrambi.
